# itr 4.1 — Coproc Memory Grow + Extensible Re-lay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow the coproc BRAM 16→48 KB, relocate the two task blobs into the new space, and re-lay both SDRAM banks to MAX-sized fixed regions (with 2-byte plots and a 64-bit discovery bitmap) so future content never forces another layout migration.

**Architecture:** Three coupled moves — (1) gateware widens BRAM and the load-address path; (2) the SDRAM equate maps move to MAX-sized bases (count ≠ layout); (3) the farm/workshop blobs relocate to the new BRAM ORGs and adopt 2-byte plots + an 8-byte disc bitmap. A single CVER=4 cold-seed migrates both banks; the //e is the sole seeder, writing each bank while its task is dead. Reflash + stale-artifact gates are baked into the final task.

**Tech Stack:** Verilog (ECP5 / Yosys / nextpnr, iverilog `-g2005` sim), Merlin32 6502 assembly (single-space source, labels col 0), GNU make. Source of truth: `docs/superpowers/specs/2026-06-16-itr4.1-memory-grow-relay-design.md`.

**Two address spaces — do not conflate:**
- **//e host** (`FARM.S`) runs at `ORG $2000` in Apple II RAM. UNCHANGED by this plan (already relocated last increment). The Makefile `FARM BIN 0x2000` import stays.
- **Coproc BRAM** (Arlet soft-core): `FARMTASK.bin` / `WORKTASK.bin` blobs load into coproc BRAM at coproc ORGs. THESE move ($0600→$2000, $2000→$4000). Their load address lives in `LOADF`/`LOADW`/`STAGE*` + TABLE-vector pokes in `FARM.S`, NOT in the Makefile.

**Sim gate per task:** every code task ends green on `make DESIGN=project_obscurus REV=rev2 sim PLUSARGS=+farmonly` (~90 s) at minimum; the final task runs the full suite (~9 min). The testbench `gateware/rev2/project_obscurus/project_obscurus_tb.v` asserts SDRAM bank bytes by absolute address — its hardcoded addresses move with the re-lay, so tb edits ship inside the task that moves the data.

**NEVER flash without explicit user permission.** This plan ends at a clean synthesized bitstream + green full suite. Deploy (flash + BRUN) is the user's call.
