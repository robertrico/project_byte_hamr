# TRADE UI — Phase 2B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the player-facing TRADE screen (NPC picker → per-NPC drill-in with live prices + sell/buy) on top of the Phase 2A trade engine, making purchaser/vendor trading playable.

**Architecture:** All in `software/SDM/FARM.S` (//e host), following the existing market/inventory screen idiom. Two new `SCREEN` states: picker (`4`) and drill-in (`5`). A static NPC-roster + item-curation table drives both screens. The drill-in reads NPC prices live from SDRAM each paint; a per-`MLOOP` `TRADETICK` repaints on price change (event-independent — see spec, resolves the goods-heartbeat wrinkle). Trades reuse the 2A ops via a generalized qty modal. No blob/SDRAM/CVER change (2A built + seeded the engine).

**Tech Stack:** Merlin32 6502 assembly (single-space source, labels col 0, one leading space for unlabeled lines, ASCII, ≤50 char lines). `make farm` / `make sdmdisk`. Validated by bench play (paint code is not FARM_TEST-able; the engine beneath is already 2A-green).

**Spec:** `docs/superpowers/specs/2026-06-18-trade-ui-phase2b-design.md`.

**No automated tests:** this is //e paint code — rendering can't be asserted via SDRAM readback (same as the existing market/inventory screens). Each task's verification is "assembles clean"; functional verification is the Task 5 bench run. The 2A FARM_TEST suite remains the engine regression guard.

## Reference: how the data maps (read once before starting)

**NPC roster** (display order 0–5): GROCER, TRADER, SEEDSHOP, BULK, EXOTIC, BAKER.

| idx | role | op-npc-index | items | op(s) |
|---|---|---|---|---|
| 0 GROCER | sell (purchaser) | 0 | 4 crops | OPTSELL |
| 1 TRADER | sell | 1 | berry,pumpkin (crop) + goods 8,9,10,11 | OPTSELL (crop) / WOPTSELL (good) |
| 2 SEEDSHOP | buy (vendor) | 2 | 4 seeds | OPTBUY |
| 3 BULK | buy | 3 | 4 seeds | OPTBUY |
| 4 EXOTIC | buy | 4 | 4 seeds | OPTBUY |
| 5 BAKER | sell | 0 | 12 goods | WOPTSELL |

**Per-item:** type 0 = crop (id 0–3), type 1 = good (recipe id 0–11).
- **Price address:** crop → `FNPC + opnpc*32 + id*2` (bank 32, `FRD`); good → `WBNPC + opnpc*128 + id*2` (bank 33, `WFRD`). Price = low byte (`SDM_VAL`).
- **HAVE column:** crop+sell → `CROP4[id]`; crop+buy → `SEED4[id]`; good → `WGOODS[id]`.
- **Op + args:** crop+sell → `SENDCMD` OPTSELL (CMDA0=opnpc, CMDA1=id, CMDA2=qty); crop+buy → `SENDCMD` OPTBUY (same arg layout); good → `WSENDCMD` WOPTSELL (CMDA02=opnpc, CMDA12=id, CMDA22=qty) → per-unit in `WRES1V`, then credit cash via `OPADDC` (qty×WRES1V), exactly as `ISQGOOD` does.

Op codes (FARMEQU.S): `OPTSELL=$08`, `OPTBUY=$09`, `WOPTSELL=$06`, `OPADDC=$06`(farm), `ROK=$01`. NPC equates: `FNPC=$0B00`, `WBNPC=$0500`, `NPGROC..NPBAKE` etc. Helpers: `FRD`/`WFRD` (A=lo,Y=hi → `SDM_VAL`), `SENDCMD`/`WSENDCMD`, `PRSTR` (MSGPTR+PRCOL+Y), `PRDEC3` (T16+X col+Y row), `MKCLR`, `CLRMSG`, `HUDCASH`, `RDMKT`, `WSYNC`. Name tables: `SNAML`/`SNAMH` (crops), `RNAML`/`RNAMH` (goods). Cursor-marker idiom: `LDY row / LDA GRLO,Y / STA LINEP / LDA GRHI,Y / STA LINEP+1 / LDA #$BE / LDY #0 / STA (LINEP),Y`.
