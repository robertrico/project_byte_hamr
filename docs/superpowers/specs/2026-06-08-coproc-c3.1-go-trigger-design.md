# Coprocessor C3.1 — GO Trigger (platform-hardening) (design)

**Date:** 2026-06-08
**Branch:** `coproc` (continues from C3, bench-verified `CPRACE3 0102/0201`)
**Board:** Byte Hamr Rev 2, `gateware/rev2/project_obscurus/` + `software/SDM/`
**Status:** approved-in-discussion, pending spec review
**Builds on:** [[project_coproc_c0]] C3 — preemptive scheduler.

## Why this exists

A real cross-run footgun surfaced on the bench: run `CPRACE3` then `CPRACE` (no reset) and
`CPRACE`'s first race prints stale results. **Root cause:** the kernel re-bootstraps on a
`COUNT` **0→nonzero level edge** (`KWAIT0` waits for 0, `KWAITN` for nonzero), but `COUNT`
(`$E010`) is host-owned and **read-only to the coproc** — the kernel can't reset it. So a
program that leaves `COUNT=2` strands the kernel in `KWAIT0`; the next loader's `STA COUNT=2`
(no value change) produces no edge → no re-bootstrap → it reads stale result cells. Ctrl-Reset
zeroes `COUNT` and hides it. This is a host-protocol footgun, but **the goal is a robust
platform** — so harden the silicon so a sloppy loader *can't* trigger it.

## Goal

A `CP_COUNT` **write** (any value, regardless of prior `COUNT`) triggers exactly one fresh
re-bootstrap. Stacking programs with no reset between just works — each loader's race reads
fresh state, never stale. Success = `CPRACE3` then `CPRACE` (no reset) both print correct
results, in sim and on the bench, and the C2/C3 races still pass.

## Architecture

Key off the **write event**, not the `COUNT` level. No new host register — reuse the
existing `CP_COUNT` write strobe.

### Gateware — `go_pending` in `coproc.v` (~8 lines)
The top already pulses `count_wr` (= `reg_wr & wr_addr_latch==4'hD`, a write to `$C0CD`
CP_COUNT) into the coproc, and `task_count` latches the value. Add a self-clearing trigger:
```
wire is_e014 = (AB==16'hE014);
reg  go_pending;
always @(posedge clk or negedge rst_n)
    if (!rst_n)                  go_pending <= 1'b0;
    else if (count_wr)           go_pending <= 1'b1;   // ANY CP_COUNT write = GO pulse (set wins)
    else if (is_e014 & WE & rdy) go_pending <= 1'b0;   // kernel ack
```
DI mux: `is_e014_q ? {7'b0, go_pending} : ...` (kernel reads status at `$E014`). So **every**
`STA CP_COUNT` sets `go_pending` — even `2`-when-already-`2` — while the value still lands in
`task_count`. **Collision:** `count_wr` (set) has priority over the ack (clear) so a GO is
never lost. Reset → `go_pending=0`.

### Kernel — `KWAITGO` replaces the level wait (`kernel.S`)
Replace:
```
KWAIT0: LDA COUNT / BNE KWAIT0      ; wait COUNT==0   <- footgun
KWAITN: LDA COUNT / BEQ KWAITN      ; wait COUNT!=0
```
with:
```
KWAITGO: LDA $E014 / BEQ KWAITGO    ; wait go_pending
         STA $E014                  ; ack (any write clears)
         JSR BOOTSTRAP              ; reads COUNT fresh, sets up tasks, arms timer, runs
```
`COUNT` (`$E010`) is still read inside `BOOTSTRAP` (task count) — it is just no longer the
trigger. `KIDLE` still disarms the timer, then `JMP KWAITGO` (wait for the next GO). At reset
`go_pending=0`, so the kernel idles in `KWAITGO` until the first `CP_COUNT` write — no
"COUNT==0 first" assumption anywhere.

### Loaders — drop the `COUNT=0` dance + zero result cells (`CPRACE.S`, `CPRACE3.S`)
Each race = load tasks/NPARAM, then a single `STA CP_COUNT` (= the GO). The re-arm = set
NPARAM, `STA CP_COUNT` (no `COUNT=0` preamble). **Also zero the SDRAM result cells
(`$0061`/`$0062`) via the monitor port before each `WAITRACE`** so a genuinely stuck race
shows obvious `00` rather than misleading stale data (belt-and-suspenders; the GO fix means a
stuck race shouldn't happen, but the zeroing makes any future failure legible).

## Data flow
```
(boot) coproc reset -> go_pending=0 -> kernel idles in KWAITGO
loaderA: load tasks + NPARAM ; STA CP_COUNT=2  -> count_wr -> go_pending=1
kernel: KWAITGO sees go_pending -> ack ($E014) -> BOOTSTRAP(reads COUNT=2) -> race -> KIDLE(disarm) -> KWAITGO
loaderB (no reset): load + STA CP_COUNT=2 -> count_wr -> go_pending=1 (regardless of COUNT's leftover value)
kernel: KWAITGO -> ack -> BOOTSTRAP -> fresh race   (no stale state)
```

## Components / files (branch `coproc`)
- `coproc.v` — add `go_pending` (set by `count_wr`, cleared by `$E014` write) + the `$E014`
  read in the DI mux (registered select `is_e014_q`, like `is_count_q`).
- `project_obscurus_top.v` — no change (`count_wr` already wired to the coproc).
- `kernel.S` — replace `KWAIT0/KWAITN` with `KWAITGO` (read `$E014`, `BEQ` wait, `STA $E014`
  ack, then `JSR BOOTSTRAP`); `KIDLE` ends `JMP KWAITGO`. (Remove the `COUNT` label if now
  unused except inside BOOTSTRAP.) Re-bake `kernel.mem`. Verify the API table + `$1F00` ISR
  offset are unaffected.
- `software/SDM/CPRACE.S`, `CPRACE3.S` — drop the `COUNT=0` writes; each race is one
  `STA CPCOUNT`; zero `$0061`/`$0062` before each read.
- `project_obscurus_tb.v` — the **regression**: run two race scenarios back-to-back with NO
  coproc reset between, and assert the second reads fresh (correct) results — the exact case
  the bench exposed. Keep the existing C3 preemptive + C2 cooperative races (they now use the
  GO trigger; update their `wr_reg(4'hD,...)` re-arm to the no-COUNT=0 form).

## Error handling / edge cases
- **Collision (`count_wr` + ack same cycle):** set wins → GO not lost.
- **Mid-race `CP_COUNT` write:** sets `go_pending` while tasks run; the kernel only consumes
  it at `KWAITGO` (after the current race's `KIDLE`). Latched, acted on next — benign; the
  host protocol still waits for completion before re-racing.
- **Reset:** `go_pending=0`; kernel idles in `KWAITGO`. Ctrl-Reset mid-race → coproc reset →
  kernel re-enters `KWAITGO`, timer disarmed (reset), no spurious GO.
- **Count-last still holds:** the host loads tasks while the kernel is idle in `KWAITGO` (no
  BRAM writes), then writes `CP_COUNT` last (= GO). The single-write-port collision guard is
  unaffected.

## Testing
- **Sim (regression):** load + race scenario A (NPARAM 4/12 → 1/2), then WITHOUT resetting the
  coproc, load scenario B with different NPARAM and write `CP_COUNT` again, assert B reads its
  own fresh result (not A's stale cells). This is the bench bug as a sim assertion.
- **Sim:** the C3 preemptive race + flip and the C2 cooperative race + flip still pass (with
  the simplified no-COUNT=0 re-arm). iverilog `-g2005`.
- **Build:** re-bake `kernel.mem`; DP16KD 8, timing PASS, `go_pending` adds one FF + a decode.
- **Bench:** flash; `BRUN CPRACE3` then `BRUN CPRACE` **with no reset between** → both correct
  (`CPRACE3` `0102`/`0201`, `CPRACE` `0102`/`0201`). The footgun is closed.

## Success criteria
A `CP_COUNT` write always triggers a fresh re-bootstrap independent of leftover `COUNT`, so
stacking host programs with no reset reads fresh state every time — the "loader left stale
level-state" bug class is removed at the silicon level. C2/C3 races unaffected.

## Non-goals
- No change to the scheduler/context-switch/timer themselves (C3 stays as built).
- No per-task generation counters or richer host↔coproc handshake beyond the single GO pulse.
- C-flash, multi-core — separate rungs.
